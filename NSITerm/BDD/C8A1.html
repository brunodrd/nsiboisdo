    🔎 Activité de découverte : les limites d'un fichier unique⚓︎

    Programme

    Contenus Capacités attendues Commentaires
    Base de données relationnelle. Savoir distinguer la structure d'une base de données de son contenu. Repérer des anomalies dans le schéma d'une base de données. Les anomalies peuvent être des redondances de données ou des anomalies d'insertion, de suppression, de mise à jour. On privilégie la manipulation de données nombreuses et réalistes.

    À la fin de cette activité, je sais…

    1. Estimer la taille d'un fichier de données et le coût d'une recherche dans ce fichier.
    2. Expliquer pourquoi une saisie libre empêche d'interroger correctement des données.
    3. Repérer une redondance, une anomalie de mise à jour, une anomalie d'insertion et une anomalie de suppression.
    4. Répartir des données dans plusieurs tables reliées par des identifiants, sans perdre d'information.

    Cette activité dure deux heures et se fait sur machine, par binôme. Elle réutilise le travail de première sur les données en table : lecture d'un fichier csv, recherche dans une table, fusion de deux tables. Pour l'instant, on oublie tout ce que l'on sait ou croit savoir sur les bases de données.

    1. 🏛️ Le contexte⚓︎

    Une bibliothèque veut une application pour gérer ses prêts.

    Chaque livre de la bibliothèque existe en un ou plusieurs exemplaires. Pour chaque exemplaire, on enregistre :

    • un numéro d'exemplaire, différent pour chaque exemplaire, même quand il s'agit du même livre ;
    • le titre du livre ;
    • son ou ses auteurs ;
    • son éditeur.

    Pour chaque emprunt, on enregistre le nom, le prénom, le numéro de téléphone et l'adresse de l'abonné, la date de l'emprunt, puis la date du retour. La bibliothèque veut garder l'historique de tous les emprunts.

    2. 📄 Une solution simple : un seul fichier⚓︎

    Le développeur choisit la solution la plus simple : tout est rangé dans un seul fichier texte au format csv, nommé biblio.csv.

    • Au départ, le fichier contient une ligne par exemplaire. Les colonnes id_ex, titre, auteur et editeur sont remplies, les autres sont vides.
    • Quand un exemplaire est emprunté pour la première fois, sa ligne est complétée avec les colonnes nom, prenom, tel, adresse et date_emp.
    • Au retour du livre, la colonne date_ret est complétée.
    • Quand le même exemplaire est emprunté à nouveau, une nouvelle ligne est ajoutée à la fin du fichier.

    Rappel : le vocabulaire de première

    Un fichier csv représente une table. Chaque ligne du fichier est un enregistrement. La première ligne donne les noms des colonnes, appelés descripteurs. En Python, on représente une table par une liste de dictionnaires : un dictionnaire par enregistrement, dont les clés sont les descripteurs.

    Le programme suivant charge la table en mémoire. Toutes les valeurs lues sont des chaînes de caractères.

    import csv

def charger(nom_fichier):
    """Renvoie la table du fichier csv : une liste de dictionnaires."""
    with open(nom_fichier, encoding='utf-8', newline='') as fichier:
        return list(csv.DictReader(fichier))

biblio = charger('biblio.csv')

    3.6 Bilan⚓︎

    Définition : redondance et anomalies

    • Il y a redondance quand une même information est écrite à plusieurs endroits.
    • Il y a anomalie de mise à jour quand la modification d'une seule information oblige à modifier plusieurs lignes : si l'une d'elles est oubliée, les données se contredisent.
    • Il y a anomalie d'insertion quand on ne peut pas enregistrer une information sans en enregistrer une autre, qui n'existe pas encore.
    • Il y a anomalie de suppression quand la suppression d'une information en fait disparaître une autre, qu'on voulait garder.

    5. 🧠 Synthèse⚓︎

    À retenir

    • Un fichier unique oblige à répéter les mêmes informations : c'est la redondance.
    • La redondance provoque des anomalies de mise à jour, d'insertion et de suppression.
    • Un fichier texte accepte n'importe quelle ligne : rien ne garantit que les données restent correctes.
    • On supprime la redondance en répartissant les données dans plusieurs tables. Chaque table décrit une seule sorte d'objets, et un numéro permet de désigner une ligne depuis une autre table.
    • Cette répartition ne perd aucune information : on retrouve la table d'origine en fusionnant les tables.

    Deux problèmes restent entiers. Les fichiers acceptent toujours des lignes fausses, comme à la question 19. Et il faut désormais parcourir plusieurs tables pour répondre à une question simple, comme à la question 26.

    Le cours C8C1 donne le vocabulaire exact de cette organisation en plusieurs tables : c'est le modèle relationnel. Le numéro qui désigne une ligne s'y appelle une clé primaire (cours C8C1, section 4), et la colonne qui renvoie vers une autre table s'y appelle une clé étrangère (cours C8C1, section 5). Les règles qui interdisent les lignes fausses s'y appellent des contraintes d'intégrité (cours C8C1, section 6). Le logiciel qui fait respecter ces règles, qui cherche vite et qui gère plusieurs utilisateurs à la fois est présenté dans le cours C8C4.
