    📖 Cours 3 : Langage SQL⚓︎

    Programme

    Contenus Capacités attendues Commentaires
    Langage SQL : requêtes d'interrogation et de mise à jour d'une base de données. Identifier les composants d'une requête. Construire des requêtes d'interrogation à l'aide des clauses du langage SQL : SELECT, FROM, WHERE, JOIN. Construire des requêtes d'insertion et de mise à jour à l'aide de : UPDATE, INSERT, DELETE. On peut utiliser DISTINCT, ORDER BY ou les fonctions d'agrégation sans utiliser les clauses GROUP BY et HAVING.

    À la fin de ce chapitre, je sais…

    1. Identifier les composants d'une requête SQL et dire à quoi sert chacun.
    2. Écrire une requête qui choisit des colonnes et des lignes d'une table avec SELECT, FROM et WHERE.
    3. Combiner plusieurs conditions avec AND, OR et NOT.
    4. Affiner un résultat avec DISTINCT et ORDER BY.
    5. Calculer un nombre de lignes, un minimum, un maximum, une somme ou une moyenne avec une fonction d'agrégation.
    6. Croiser deux ou trois tables avec JOIN ... ON.
    7. Modifier le contenu d'une table avec INSERT, UPDATE et DELETE.
    8. Prévoir si une modification sera refusée à cause d'une contrainte d'intégrité.

    Tout le cours s'appuie sur la base Livres_2, déjà utilisée au cours C8C1. Voici son schéma. La clé primaire de chaque relation est soulignée et les clés étrangères sont précédées du signe #.

    • livre (titre, editeur, annee, isbn)
    • auteur (a_id, nom, prenom)
    • auteur_de (#a_id, #isbn)
    • usager (nom, prenom, adresse, cp, ville, email, code_barre)
    • emprunt (#code_barre, #isbn, retour)

    Les attributs annee, a_id, cp et code_barre sont des entiers. L'attribut retour est une date. Tous les autres sont des textes. Dans auteur_de, la clé primaire est le couple (a_id, isbn) : un livre peut avoir plusieurs auteurs et un auteur plusieurs livres.

    0. 🔎 Activité d'amorce : lire avant d'écrire⚓︎

    À faire

    Voici une requête SQL. Ne l'exécutez pas tout de suite.

    1
2
3
4
    SELECT titre, annee
FROM livre
WHERE annee >= 1990
ORDER BY annee;
    1. Sans machine, décrire par une phrase ce que cette requête demande.
    2. Combien de colonnes aura le résultat ? Peut-on prévoir son nombre de lignes ?
    3. Exécuter la requête et comparer avec vos prévisions.
    4. Modifier un seul mot ou un seul nombre à la fois, puis observer ce qui change dans le résultat.

    1. 📚 Le langage SQL⚓︎

    Définition : SQL

    SQL (Structured Query Language) est le langage normalisé qui permet de dialoguer avec un système de gestion de bases de données relationnelles. Un texte écrit en SQL s'appelle une requête. Elle se termine par un point-virgule.

    SQL est un langage déclaratif : la requête décrit le résultat voulu, elle ne dit pas comment l'obtenir. On n'écrit ni boucle ni parcours de table. C'est le système de gestion de bases de données qui choisit la méthode (cours C8C4).

    Le programme distingue deux familles de requêtes :

    • les requêtes d'interrogation, qui lisent la base sans la modifier : elles commencent par SELECT ;
    • les requêtes de mise à jour, qui modifient le contenu de la base : elles commencent par INSERT, UPDATE ou DELETE.

    Propriété : le résultat d'une interrogation est une table

    Une requête d'interrogation renvoie toujours une table : des colonnes nommées et zéro, une ou plusieurs lignes. Cette table est calculée au moment de la requête. Elle n'est pas enregistrée dans la base.

    Une requête est formée de clauses. Chaque clause commence par un mot-clé et joue un rôle précis.

    Clause Rôle Obligatoire
    SELECT choisir les colonnes du résultat oui
    FROM indiquer la table à lire oui
    JOIN ... ON ajouter une autre table et dire comment relier les lignes non
    WHERE garder seulement les lignes qui vérifient une condition non
    ORDER BY trier les lignes du résultat non

    Les clauses s'écrivent toujours dans cet ordre. Les mots-clés s'écrivent en majuscules par convention : SQL accepte aussi les minuscules, mais la requête est plus facile à lire ainsi.

    2. 🎯 Interroger une table : SELECT, FROM, WHERE⚓︎

    2.1 Choisir des colonnes⚓︎

    La forme la plus simple d'une interrogation est SELECT attributs FROM table;. Les attributs sont séparés par des virgules.

    1
2
    SELECT titre, annee
FROM livre;

    Le résultat contient une ligne par livre et deux colonnes. Pour obtenir toutes les colonnes, on écrit * à la place de la liste des attributs.

    1
2
    SELECT *
FROM livre;

    2.2 Choisir des lignes⚓︎

    La clause WHERE est suivie d'une condition. Seules les lignes pour lesquelles la condition est vraie sont gardées.

    1
2
3
    SELECT titre, annee
FROM livre
WHERE editeur = 'Dargaud';
    Opérateur Signification
    = égal
    <> différent
    <, <= strictement inférieur, inférieur ou égal
    >, >= strictement supérieur, supérieur ou égal

    Attention : textes et dates entre apostrophes

    Une valeur de type texte s'écrit entre apostrophes droites : 'Dargaud'. Un nombre s'écrit sans apostrophes : 1990. Avant d'écrire une condition, on regarde donc le domaine de l'attribut dans le schéma : ici cp et code_barre sont des entiers, on écrit cp = 75012. Une date s'écrit entre apostrophes au format 'AAAA-MM-JJ' : retour < '2020-02-01' signifie « avant le 1er février 2020 ».

    2.3 Combiner des conditions⚓︎

    Les opérateurs logiques AND, OR et NOT ont le même sens qu'en Python.

    1
2
3
    SELECT titre
FROM livre
WHERE editeur = 'Dargaud' AND annee < 1980;

    1
2
3
    SELECT nom, prenom
FROM usager
WHERE cp = 75012 OR cp = 75013;

    Attention : priorité de AND sur OR

    AND est prioritaire sur OR. La condition a OR b AND c est lue a OR (b AND c). Dès qu'une condition mélange les deux opérateurs, on met des parenthèses.

    2.4 Tester une valeur absente⚓︎

    Quand un attribut n'a pas de valeur dans une ligne, il contient le marqueur NULL. Ce marqueur ne se compare pas avec =. On écrit IS NULL ou IS NOT NULL.

    1
2
3
    SELECT nom, prenom
FROM usager
WHERE email IS NULL;

    Dans la base Livres_2, tous les usagers ont une adresse électronique : le résultat de cette requête est une table sans aucune ligne. Ce n'est pas une erreur.

    Hors programme : comparer un texte à un motif avec LIKE

    L'opérateur LIKE compare un texte à un motif. Dans le motif, le caractère % remplace une suite quelconque de caractères, éventuellement vide. Cet opérateur n'est pas exigible : un sujet qui l'utilise le rappelle dans son énoncé.

    1
2
3
    SELECT titre
FROM livre
WHERE titre LIKE 'A%';

    Cette requête donne les titres qui commencent par la lettre A. Avec le motif '%Astérix%', on obtient les titres qui contiennent le mot Astérix.

    À faire

    Écrire puis tester une requête pour chaque demande.

    1. Toutes les informations sur les livres publiés par l'éditeur Dargaud.
    2. Le titre et l'année des livres publiés strictement après 1990.
    3. Le nom et l'adresse des usagers dont le code postal est 75012.
    4. Le titre des livres publiés entre 1950 et 1960, bornes comprises.
    5. Le titre des livres qui ne sont publiés ni en 1999 ni en 2011.

    3. 🧹 Affiner le résultat : DISTINCT et ORDER BY⚓︎

    Une interrogation peut renvoyer plusieurs lignes identiques. Le mot-clé DISTINCT, placé juste après SELECT, ne garde qu'un exemplaire de chaque ligne.

    1
2
    SELECT DISTINCT annee
FROM livre;

    La clause ORDER BY trie les lignes du résultat selon un attribut. Le tri est croissant par défaut (ASC). On ajoute DESC pour un tri décroissant.

    1
2
3
4
    SELECT titre, annee
FROM livre
WHERE annee > 1990
ORDER BY annee DESC;

    On peut donner plusieurs critères, séparés par des virgules : le second sert à départager les lignes égales pour le premier.

    1
2
3
    SELECT nom, prenom
FROM usager
ORDER BY nom, prenom;

    Attention : sans ORDER BY, aucun ordre n'est garanti

    Une relation est un ensemble de n-uplets : ses lignes n'ont pas d'ordre. Si une question demande un résultat trié, la requête doit contenir ORDER BY.

    À faire

    1. Comparer les résultats de SELECT annee FROM livre; et de SELECT DISTINCT annee FROM livre;.
    2. Écrire une requête qui donne les noms des auteurs par ordre alphabétique.
    3. Écrire une requête qui donne les éditeurs présents dans la base, sans répétition, par ordre alphabétique.

    4. 🧮 Calculer sur une colonne : les fonctions d'agrégation⚓︎

    Une fonction d'agrégation calcule une seule valeur à partir de toutes les lignes gardées par la requête.

    Fonction Valeur calculée
    COUNT(*) nombre de lignes
    COUNT(DISTINCT attribut) nombre de valeurs différentes de l'attribut
    MIN(attribut), MAX(attribut) plus petite valeur, plus grande valeur
    SUM(attribut) somme des valeurs
    AVG(attribut) moyenne des valeurs 
    1
2
3
    SELECT COUNT(*)
FROM livre
WHERE annee < 1980;

    Cette requête donne le nombre de livres publiés avant 1980. Le résultat est une table d'une ligne et d'une colonne.

    1
2
    SELECT MIN(annee), MAX(annee)
FROM livre;

    1
2
    SELECT COUNT(DISTINCT editeur)
FROM livre;

    Attention : pas d'attribut ordinaire à côté d'une agrégation

    La requête SELECT titre, MIN(annee) FROM livre; n'a pas de sens au programme : MIN(annee) donne une seule valeur alors que titre en a une par ligne. Les clauses GROUP BY et HAVING, qui traitent ce cas, sont hors programme.

    À faire

    1. Combien d'usagers la base contient-elle ?
    2. Combien de livres sont actuellement empruntés ?
    3. Quelle est l'année de publication du livre le plus récent de l'éditeur Dargaud ?

    5. 🔗 Croiser plusieurs tables : JOIN⚓︎

    5.1 Le principe⚓︎

    La table emprunt contient l'ISBN des livres empruntés, pas leur titre. Le titre se trouve dans la table livre. Pour afficher le titre des livres empruntés, il faut rapprocher chaque ligne de emprunt de la ligne de livre qui a le même ISBN. Cette opération s'appelle une jointure.

    Exemple : jointure sur des extraits des deux tables

    Extrait de livre :

    titre editeur annee isbn
    Lolita Penguin UK 2012 978-0141391601
    Mrs Dalloway Flammarion 2015 978-2081358881
    La Planète des singes Julliard 2011 978-2260019183

    Extrait de emprunt :

    code_barre isbn retour
    421921003090881 978-2081358881 2020-04-28
    934701281931582 978-2260019183 2020-01-01

    Requête :

    1
2
3
    SELECT livre.titre, emprunt.retour
FROM emprunt
JOIN livre ON emprunt.isbn = livre.isbn;

    Résultat sur ces extraits :

    titre retour
    Mrs Dalloway 2020-04-28
    La Planète des singes 2020-01-01

    Le livre Lolita n'apparaît pas : aucune ligne de emprunt ne porte son ISBN.

    Définition : jointure

    La jointure de deux tables selon une condition construit toutes les lignes obtenues en accolant une ligne de la première table et une ligne de la seconde, à condition que ces deux lignes vérifient la condition écrite après ON. Le plus souvent, cette condition est l'égalité entre une clé étrangère et la clé primaire qu'elle référence.

    Quand deux tables ont un attribut de même nom, on lève l'ambiguïté en le préfixant par le nom de sa table : emprunt.isbn, livre.isbn. Préfixer tous les attributs d'une requête avec jointure est une bonne habitude.

    5.2 Jointure et sélection⚓︎

    Après une jointure, on dispose des attributs des deux tables. La clause WHERE peut porter sur n'importe lequel.

    1
2
3
4
    SELECT livre.titre, emprunt.retour
FROM emprunt
JOIN livre ON emprunt.isbn = livre.isbn
WHERE emprunt.retour < '2020-02-01';

    À ne pas confondre

    La condition qui suit ON dit comment relier les lignes des deux tables : c'est presque toujours une égalité entre une clé étrangère et une clé primaire. La condition qui suit WHERE dit quelles lignes garder une fois les tables reliées. Une jointure dont le ON ne relie pas les bonnes clés donne un résultat faux, même si la requête s'exécute sans erreur.

    5.3 Enchaîner deux jointures⚓︎

    Pour connaître l'auteur d'un livre, il faut passer par la table auteur_de, qui relie livre et auteur. On enchaîne alors deux jointures : chaque JOIN ajoute une table et son ON la relie à une table déjà présente.

    1
2
3
4
5
    SELECT auteur.nom, auteur.prenom
FROM livre
JOIN auteur_de ON livre.isbn = auteur_de.isbn
JOIN auteur ON auteur_de.a_id = auteur.a_id
WHERE livre.titre = '1984';

    Méthode : construire une requête avec jointure

    1. Repérer dans la question les attributs à afficher et ceux qui servent de critère.
    2. Noter dans quelle table se trouve chacun de ces attributs.
    3. Sur le schéma, suivre les clés étrangères qui relient ces tables : chaque lien donne un JOIN ... ON. S'il faut passer par une table intermédiaire, elle entre aussi dans la requête.
    4. Écrire la clause WHERE avec les critères.
    5. Terminer par SELECT, en ajoutant DISTINCT ou ORDER BY si la question le demande.
    Hors programme : renommer une table avec AS

    On peut donner un nom court à une table dans une requête : FROM emprunt AS e JOIN livre AS l ON e.isbn = l.isbn. Les attributs s'écrivent alors e.retour, l.titre. Ce raccourci n'est pas exigible, mais il se rencontre dans des énoncés.

    À faire

    1. Le titre des livres empruntés à rendre avant le 31 mars 2020.
    2. Le nom et le prénom des usagers qui ont un emprunt en cours, sans répétition, par ordre alphabétique des noms.
    3. Le titre des livres écrits par un auteur dont le nom est Asimov.
    4. Le nombre de livres empruntés par l'usager dont le code-barres est 421921003090881. Une jointure est-elle nécessaire ?

    6. 🔄 Modifier le contenu : INSERT, UPDATE, DELETE⚓︎

    Ces trois requêtes modifient le contenu de la base. Elles ne changent pas sa structure : le schéma reste le même (cours C8C2). À chaque modification, le système vérifie les contraintes d'intégrité vues au cours C8C1. Si l'une d'elles n'est plus respectée, la requête est refusée et la base reste inchangée.

    6.1 Ajouter des lignes : INSERT⚓︎

    1
2
    INSERT INTO auteur (a_id, nom, prenom)
VALUES (9001, 'Devi', 'Ananda');

    On donne la liste des attributs, puis les valeurs dans le même ordre. On peut omettre la liste des attributs : il faut alors donner une valeur pour chaque attribut, dans l'ordre du schéma.

    1
2
    INSERT INTO livre
VALUES ('Le Sari vert', 'Gallimard', 2009, '978-2070127894');

    Deux refus sont à prévoir :

    • la valeur de la clé primaire existe déjà dans la table (contrainte de relation) ;
    • la valeur d'une clé étrangère n'existe pas dans la table référencée (contrainte de référence).

    Pour enregistrer qu'Ananda Devi est l'autrice du livre « Le Sari vert », il faut donc que les deux insertions ci-dessus aient déjà été faites.

    1
2
    INSERT INTO auteur_de (a_id, isbn)
VALUES (9001, '978-2070127894');

    6.2 Modifier des lignes : UPDATE⚓︎

    La requête UPDATE table SET attribut = valeur WHERE condition; change la valeur d'un ou plusieurs attributs dans toutes les lignes qui vérifient la condition.

    1
2
3
    UPDATE usager
SET email = 'david@payet.re'
WHERE code_barre = 934701281931116;

    Pour modifier plusieurs attributs, on les sépare par des virgules après SET.

    1
2
3
    UPDATE usager
SET adresse = '12 rue des Lilas', cp = 97400, ville = 'Saint-Denis'
WHERE code_barre = 934701281931116;

    6.3 Supprimer des lignes : DELETE⚓︎

    La requête DELETE FROM table WHERE condition; supprime toutes les lignes qui vérifient la condition.

    1
2
    DELETE FROM emprunt
WHERE isbn = '978-2260019183';

    Attention : UPDATE et DELETE sans WHERE

    Sans clause WHERE, UPDATE modifie toutes les lignes de la table et DELETE les supprime toutes. Pour viser une seule ligne, la condition porte sur la clé primaire.

    Attention : supprimer une ligne référencée

    On ne peut pas supprimer une ligne tant qu'une clé étrangère d'une autre table fait référence à elle. Pour supprimer un usager, il faut d'abord supprimer ses emprunts. Pour supprimer un livre, il faut d'abord supprimer les lignes de auteur_de et de emprunt qui portent son ISBN.

    À faire

    Travailler sur la base indiquée par le professeur.

    1. Insérer un nouvel usager, puis vérifier sa présence avec une interrogation.
    2. Tenter d'insérer un second usager avec le même code-barres. Quelle contrainte explique le refus ?
    3. Tenter d'insérer un emprunt pour un ISBN qui n'existe pas dans livre. Quelle contrainte explique le refus ?
    4. Modifier l'adresse électronique de l'usager créé à la question 1.
    5. Supprimer cet usager. Que faudrait-il faire d'abord s'il avait un emprunt en cours ?

    7. 🧠 Synthèse⚓︎

    À retenir

    • SQL est un langage déclaratif : la requête décrit le résultat, pas la méthode.
    • Une interrogation s'écrit dans cet ordre : SELECT, FROM, JOIN ... ON, WHERE, ORDER BY. Son résultat est une table.
    • WHERE choisit des lignes, SELECT choisit des colonnes, DISTINCT retire les doublons, ORDER BY trie.
    • Une fonction d'agrégation (COUNT, MIN, MAX, SUM, AVG) donne une seule valeur.
    • Une jointure relie deux tables par une égalité entre une clé étrangère et une clé primaire, écrite après ON. Trois tables demandent deux jointures.
    • INSERT ajoute des lignes, UPDATE en modifie, DELETE en supprime. Sans WHERE, les deux dernières agissent sur toute la table.
    • Une modification qui viole une contrainte d'intégrité est refusée.
    Besoin Requête type
    Choisir des colonnes et des lignes SELECT a, b FROM t WHERE condition;
    Retirer les doublons SELECT DISTINCT a FROM t;
    Trier SELECT a FROM t ORDER BY a DESC;
    Compter SELECT COUNT(*) FROM t WHERE condition;
    Croiser deux tables SELECT t.a, u.b FROM t JOIN u ON t.cle_etrangere = u.cle_primaire;
    Ajouter une ligne INSERT INTO t (a, b) VALUES (v1, v2);
    Modifier des lignes UPDATE t SET a = v WHERE condition;
    Supprimer des lignes DELETE FROM t WHERE condition;
