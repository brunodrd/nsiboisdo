    📖 Cours 4 : Les systèmes de gestion de bases de données⚓︎

    Programme

    Contenus Capacités attendues Commentaires
    Système de gestion de bases de données relationnelles. Identifier les services rendus par un système de gestion de bases de données relationnelles : persistance des données, gestion des accès concurrents, efficacité de traitement des requêtes, sécurisation des accès. Il s'agit de comprendre le rôle et les enjeux des différents services sans en détailler le fonctionnement.

    À la fin de ce chapitre, je sais…

    1. Distinguer une base de données du logiciel qui la gère.
    2. Citer les quatre services rendus par un système de gestion de bases de données.
    3. Expliquer le rôle et l'enjeu de chaque service sur un exemple.
    4. Reconnaître ce qui relève d'un système de gestion de bases de données et ce qui n'en relève pas.
    5. Donner des avantages d'un système de gestion de bases de données par rapport à un fichier ou à un tableur.

    0. 🔎 Activité d'amorce : la bibliothèque sans SGBD⚓︎

    Revenons à l'activité C8A1 : la bibliothèque enregistre tout dans un fichier biblio.csv, posé sur un ordinateur partagé. Un programme Python le lit et le réécrit en entier à chaque opération.

    À faire

    Pour chaque situation, dire ce qui risque de se passer.

    1. Le courant est coupé pendant que le programme réécrit le fichier.
    2. Deux bibliothécaires, sur deux postes, enregistrent au même moment un emprunt chacun. Chaque programme a lu le fichier, ajoute sa ligne, puis réécrit le fichier.
    3. Le fichier contient deux millions de lignes. Un usager demande la liste des livres qu'il a empruntés.
    4. Un stagiaire, chargé de ranger les rayons, ouvre le fichier avec un tableur. Il y voit l'adresse et le téléphone de tous les abonnés, et efface une colonne par erreur.

    Ces quatre situations correspondent aux quatre services étudiés dans ce cours.

    1. 📚 Qu'est-ce qu'un SGBD ?⚓︎

    Définition : système de gestion de bases de données

    Un système de gestion de bases de données, en abrégé SGBD, est un logiciel qui enregistre les données d'une base, les protège et exécute les requêtes qu'on lui adresse. Quand la base suit le modèle relationnel, on parle de SGBD relationnel, ou SGBDR.

    MySQL, MariaDB, PostgreSQL, Oracle Database, Microsoft SQL Server et SQLite sont des SGBD relationnels. Tous comprennent le langage SQL.

    À ne pas confondre

    La base de données est l'ensemble des données. Le SGBD est le logiciel qui les gère. Livres_2 est une base de données ; MySQL est le SGBD qui la gère. Un même SGBD gère souvent plusieurs bases.

    Le plus souvent, un SGBD fonctionne selon le modèle client-serveur vu en première : c'est un programme serveur, qui attend des requêtes. Les clients sont les programmes qui lui envoient ces requêtes.

    Ce schéma porte l'idée essentielle du cours : aucun utilisateur et aucun programme ne touche directement aux fichiers de la base. Tout passe par le SGBD. C'est parce qu'il est le seul point de passage qu'il peut rendre les quatre services qui suivent.

    Pour aller plus loin : un SGBD sans serveur

    SQLite fait exception : il n'y a pas de programme serveur. La base est un simple fichier, et le SGBD est une bibliothèque incluse dans le programme qui l'utilise, par exemple le module sqlite3 de Python. SQLite convient à une application utilisée par une seule personne à la fois. Il ne gère pas de comptes d'utilisateurs.

    2. 💾 Persistance des données⚓︎

    Définition : persistance

    Les données sont persistantes quand elles continuent d'exister après la fin du programme qui les a créées, après l'extinction de la machine, et même après une panne.

    Rôle. Le SGBD enregistre les données sur un support durable et garantit qu'une modification acceptée ne sera pas perdue. Si une panne survient au milieu d'une modification, il remet la base dans un état correct au redémarrage : la modification est soit entièrement faite, soit pas faite du tout.

    Enjeu. Les variables d'un programme Python disparaissent quand il s'arrête. Une bibliothèque, une banque ou un hôpital ne peuvent pas perdre leurs données à chaque coupure de courant, ni se retrouver avec un fichier à moitié écrit.

    3. 👥 Gestion des accès concurrents⚓︎

    Définition : accès concurrents

    Il y a accès concurrents quand plusieurs utilisateurs ou plusieurs programmes lisent et modifient la même base au même moment.

    Rôle. Le SGBD organise ces accès pour que le résultat soit le même que si les opérations avaient été faites l'une après l'autre. Aucune modification n'est perdue, et personne ne voit la base dans un état intermédiaire.

    Enjeu. Dans la situation 2 de l'amorce, les deux programmes lisent le même fichier, puis chacun le réécrit avec sa seule ligne en plus : le second écrase le travail du premier, et un emprunt disparaît. Sur un site de réservation, le même défaut vendrait deux fois la même place.

    Le problème a déjà été rencontré au chapitre VII : plusieurs processus qui partagent une ressource doivent être coordonnés, et cette coordination peut mener à un interblocage. Un SGBD rencontre les mêmes difficultés et les traite lui-même, sans que l'auteur des requêtes ait à s'en occuper.

    Hors programme : les transactions

    Pour gérer les pannes et les accès concurrents, un SGBD regroupe les opérations en transactions. Une transaction est une suite d'opérations qui est soit validée en entier (COMMIT), soit annulée en entier (ROLLBACK). Un virement bancaire en est l'exemple type : le débit d'un compte et le crédit de l'autre doivent réussir tous les deux ou échouer tous les deux. Les transactions sont observées en travaux pratiques, mais leur fonctionnement n'est pas exigible.

    4. ⚡ Efficacité du traitement des requêtes⚓︎

    Rôle. SQL est un langage déclaratif : une requête décrit le résultat voulu, pas la façon de l'obtenir (cours C8C3, section 1). C'est le SGBD qui choisit la méthode. Il dispose pour cela de techniques qui évitent de lire toutes les lignes, comme les index, comparables à l'index placé à la fin d'un livre.

    Enjeu. L'activité C8A1 l'a chiffré : parcourir un fichier de 2,4 millions de lignes pour retrouver un abonné demandait plus de quatre minutes. Un SGBD répond à la même question en une fraction de seconde, et celui qui écrit la requête n'a pas eu à programmer la recherche.

    Attention : ne pas détailler le fonctionnement

    Le programme demande de comprendre le rôle et l'enjeu de ce service, pas la façon dont un SGBD choisit sa méthode. Dans une copie, il suffit de dire que le SGBD optimise lui-même l'exécution des requêtes, ce qui permet de traiter rapidement de grands volumes de données.

    5. 🔒 Sécurisation des accès⚓︎

    Rôle. Le SGBD contrôle qui accède à la base et ce que chacun a le droit d'y faire. Ce contrôle repose sur deux mécanismes :

    • l'authentification : chaque utilisateur se connecte avec un identifiant et un mot de passe ;
    • les droits : pour chaque utilisateur, le SGBD sait quelles tables il peut consulter et quelles opérations lui sont permises.

    Sur le serveur de la classe, le compte élève peut interroger la base Livres_2 avec SELECT, mais l'administrateur ne lui a pas donné le droit d'y exécuter DELETE.

    Enjeu. Dans la situation 4 de l'amorce, le stagiaire voit tout et peut tout modifier, parce qu'un fichier s'ouvre en entier ou pas du tout. Avec un SGBD, on lui aurait donné le droit de consulter la table des livres, et rien d'autre.

    Attention : ce qui ne relève pas du SGBD

    Un SGBD ne garantit pas que les données saisies sont vraies (cours C8C1, section 6). Il n'assure pas non plus l'alimentation électrique du serveur, ni le chiffrement des pages d'un site web par le protocole HTTPS. Ces propositions servent de pièges dans les questions à choix multiples.

    Pour aller plus loin : données personnelles et RGPD

    La table usager contient des noms, des adresses postales et des adresses électroniques : ce sont des données personnelles. Le SGBD fournit les outils pour les protéger, mais c'est l'organisme qui gère la base qui en est responsable. En Europe, le règlement général sur la protection des données (RGPD), appliqué depuis 2018, fixe ses obligations. En France, la CNIL veille à son respect.

    Principe Ce qu'il impose Lien avec la base
    finalité ne collecter des données que dans un but précis et annoncé chaque attribut de usager doit servir à la gestion des prêts
    minimisation ne collecter que les données nécessaires pas d'attribut inutile dans le schéma, par exemple la profession
    conservation limitée effacer les données quand elles ne servent plus supprimer l'usager qui se désinscrit
    sécurité protéger les données contre les accès non autorisés authentification et droits du SGBD
    droits des personnes permettre à chacun de consulter, corriger ou faire effacer ses données requêtes SELECT, UPDATE, DELETE

    À faire

    1. Proposer les droits à donner sur la table usager à un bibliothécaire, puis à un stagiaire chargé du rangement.
    2. Un usager demande la liste de toutes les informations que la bibliothèque détient sur lui. Dans quelles tables de Livres_2 faut-il chercher ?

    6. ⚖️ SGBD, fichier ou tableur ?⚓︎

    Fichier CSV ou tableur SGBD
    Persistance le fichier est enregistré, mais une panne pendant l'écriture peut le laisser incomplet une modification acceptée est conservée, même après une panne
    Accès concurrents deux personnes qui modifient le fichier en même temps écrasent le travail l'une de l'autre les modifications simultanées sont coordonnées
    Efficacité il faut parcourir les lignes une à une, et programmer soi-même la recherche le SGBD choisit une méthode rapide, même sur des millions de lignes
    Sécurité des accès on ouvre tout le fichier ou rien droits accordés utilisateur par utilisateur, table par table
    Cohérence rien n'empêche une valeur absurde ou une référence vers rien les contraintes d'intégrité font refuser les modifications incorrectes

    Un fichier ou un tableur reste le bon choix pour des données peu nombreuses, utilisées par une seule personne. Dès que les données sont volumineuses, partagées ou sensibles, on passe à un SGBD.

    7. 🧠 Synthèse⚓︎

    À retenir

    • Un SGBD est le logiciel qui gère une base de données. Il est le seul à accéder aux fichiers de la base.
    • Persistance des données : les données sont conservées après l'arrêt du programme ou de la machine, même en cas de panne.
    • Gestion des accès concurrents : plusieurs utilisateurs peuvent lire et modifier la base en même temps sans créer d'incohérence.
    • Efficacité du traitement des requêtes : le SGBD choisit lui-même une méthode rapide pour exécuter chaque requête.
    • Sécurisation des accès : le SGBD authentifie les utilisateurs et limite ce que chacun a le droit de faire.
    • Le SGBD ne garantit pas que les données sont vraies.

    8. 📝 Pour s'entraîner⚓︎

    Ces questions se traitent sur papier. Sauf pour l'exercice 1, chaque réponse est rédigée par une ou plusieurs phrases complètes. L'exercice marqué ⭐ est un prolongement.

    Exercice 1 – Services d'un SGBD⚓︎

    Parmi les propositions suivantes, indiquer celles qui sont des services rendus par un SGBD.

    1. Vérifier l'identité de la personne qui se connecte à la base.
    2. Conserver les données quand le serveur est éteint puis rallumé.
    3. Garantir que les informations saisies par les utilisateurs sont exactes.
    4. Permettre à plusieurs utilisateurs de modifier la base en même temps sans incohérence.
    5. Chiffrer avec HTTPS les pages du site web qui utilise la base.
    6. Choisir une méthode rapide pour exécuter une requête.
    7. Fournir l'électricité au serveur pendant une coupure de courant.

    Exercice 2 – Quel service ?⚓︎

    Pour chaque situation, nommer le service du SGBD qui est en jeu.

    1. Un vendredi soir, des milliers de personnes réservent des billets pour le même concert. Aucune place n'est vendue deux fois.
    2. Un élève peut consulter ses notes, mais pas celles des autres, et il ne peut en modifier aucune.
    3. Le serveur d'une banque redémarre après une panne. Tous les virements validés avant la panne sont présents.
    4. Un moteur de recherche interne retrouve une commande parmi cinquante millions en moins d'une seconde.
    5. Deux secrétaires modifient le même dossier médical au même moment. Les deux modifications sont enregistrées.
    6. Un ancien salarié essaie de se connecter à la base de son entreprise. La connexion est refusée.

    Exercice 3 – SGBD ou tableur⚓︎

    Un restaurant note ses commandes dans un tableur, une ligne par commande. Un prestataire lui propose d'utiliser un SGBD relationnel.

    1. Donner deux avantages qu'un SGBD apporterait au restaurant.
    2. Le restaurateur répond que son tableur « enregistre déjà les données ». De quel service parle-t-il ? En quoi un SGBD fait-il mieux sur ce point ?
    3. Citer une situation où le tableur resterait un choix raisonnable.

    ⭐ Exercice de prolongement – Deux emprunts au même instant⚓︎

    Deux bibliothécaires veulent enregistrer au même instant l'emprunt du même livre, Lolita, par deux usagers différents. Chacun de leurs programmes procède en deux étapes : il vérifie que le livre n'est pas dans emprunt, puis il insère une ligne dans emprunt.

    1. Avec un fichier partagé et sans SGBD, décrire un déroulement des quatre étapes qui conduit à enregistrer deux emprunts pour le même livre.
    2. Dans la base Livres_2, la clé primaire de emprunt est isbn. Quelle contrainte d'intégrité empêche d'enregistrer les deux emprunts ?
    3. Quel service du SGBD garantit que cette contrainte est bien vérifiée, même si les deux insertions arrivent au même instant ?
    4. Que doit faire le programme du bibliothécaire dont l'insertion est refusée ?
